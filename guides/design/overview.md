# Design a site that fits its purpose

Use this workflow before creating or redesigning pages. For a small edit, preserve the site's established visual language and load only the relevant section. The user's brief, real brand assets and observed site take priority over these starting points.

1. **Inspect.** Open the current frontend at desktop and mobile sizes. Read representative content and identify the active theme, editor, shared header/footer, fonts, palette and available images. Record what works and what needs changing. Stored markup alone cannot establish visual quality.
2. **Frame.** State the audience, main visitor task, primary action, content requirements and scope. For missing details, use a clear provisional assumption; ask when the answer would materially change the result. See `brief`.
3. **Choose.** Name a visual direction and two or three concrete decisions that make it recognizable: image treatment, type hierarchy, composition or material detail. Explain how those decisions serve the subject. A distinctive site can be quiet. See `system`, `layout` and `motion`.
4. **Prove.** Build one representative page or section with real copy, the longest likely title and a real image before repeating it across the site. Inspect the rendered result, then adjust. See `images`.
5. **Implement.** Reuse the site's supported styles, native content models and editing interface. Keep shared decisions consistent and content editable. Discover the live schemas before writing. See `wordpress`.
6. **Review.** Check the actual page at wide, narrow and intermediate widths; test navigation, keyboard use and the main action. Fix functional and readability problems before cosmetic refinements. Report what you observed and what remains untested. See `review`.

Keep a short working note: **audience / visitor task / primary action / direction / shared design decisions / section order / image plan / verification results**. Reuse it across subsequent pages instead of reinventing the design.
