# Compose pages around content

Make the page recognizable at a glance: subject, hierarchy and next action should be clear. Establish a shared grid and align text, images, navigation and captions to it. Alignment can stay coherent while section compositions vary.

## Give sections different jobs

A hero should state the proposition and establish the visual direction. It may be compact, image-led or typographic; a giant heading and two buttons are not prerequisites. Size it so useful content remains discoverable on ordinary screens. Avoid using viewport-height sections as a default.

Let important work have more room. Alternate density and image scale where the content supports it: a featured project, a tighter collection, then a short piece of evidence. Repeating identical cards for every kind of information flattens hierarchy. Use a card when items need a shared boundary or interaction, and plain typography when that communicates better.

Keep labels close to the thing they explain. Give related items consistent image ratios, caption positions and interaction patterns. Use deliberate exceptions for featured content. On a portfolio, visible project titles and categories should help visitors choose a project before opening it.

## Design the narrow version deliberately

Choose breakpoints where the content stops working rather than treating device names as layout rules. On narrower widths, reorder only when it preserves reading and keyboard order; keep DOM order meaningful. Collapse columns, reduce section spacing and adapt image crops while retaining hierarchy. Dense pages may need a different navigation presentation rather than simply smaller type.

Use flexible widths and wrapping; fixed heights need a reason. Test long titles, multi-line buttons, empty images and uneven text lengths. Do not hide overflow globally to conceal a broken layout. Reserve media space to avoid content jumping as it loads. Sticky headers and banners must leave content and focused controls visible.

## Interaction and motion

Use links for navigation and buttons for actions. Give controls visible labels, visible keyboard focus and understandable states. A whole-card link must have a clear accessible name and must not contain conflicting nested controls. Make menus usable with keyboard and touch, including closing them and returning focus when appropriate. Content and actions must be available without hover.

Use motion to explain a state change or guide attention. Keep content available when animation fails or reduced motion is requested. Avoid delaying reading with elaborate entrance sequences or requiring scrolling tricks to navigate. Check loading, empty, success and error states when a component has them; an attractive resting screenshot is only one state of the interface.
